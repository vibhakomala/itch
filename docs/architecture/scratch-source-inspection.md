# Scratch source inspection — Phase 0

Inspected on **13 October 2026**, against `scratchfoundation/scratch-editor` develop commit [`a71aeddc290c76a8e715ef74db1d81127afbc90d`](https://github.com/scratchfoundation/scratch-editor/commit/a71aeddc290c76a8e715ef74db1d81127afbc90d). The GitHub connector resolved the current branch head and fetched files at that immutable commit. Some cached web branch pages showed older revisions, so the commit-pinned files informed this adapter. The [repository](https://github.com/scratchfoundation/scratch-editor) is the current editor monorepo; its inspected [VM package manifest](https://github.com/scratchfoundation/scratch-editor/blob/a71aeddc290c76a8e715ef74db1d81127afbc90d/packages/scratch-vm/package.json) identifies `@scratch/scratch-vm` version 15.2.0.

The [extension manager](https://github.com/scratchfoundation/scratch-editor/blob/a71aeddc290c76a8e715ef74db1d81127afbc90d/packages/scratch-vm/src/extension-support/extension-manager.js) constructs known built-in extensions with the runtime, registers their service, reads `getInfo`, and installs primitives through central dispatch. `_registerInternalExtension` is private and returns a service name; the manager's normal built-in loading path also records loaded extension IDs. Loading an unknown URL creates an extension worker. Event block metadata has no implementation function. ITCH's helper isolates the private registration call and disposes its subscription if it fails; it does not implement loaded-ID bookkeeping, project persistence, or a production distribution mechanism.

The [extension worker](https://github.com/scratchfoundation/scratch-editor/blob/a71aeddc290c76a8e715ef74db1d81127afbc90d/packages/scratch-vm/src/extension-support/extension-worker.js) imports the extension script after a dispatch handshake and exposes `Scratch.extensions.register`. A worker cannot receive the same in-memory provider object automatically. A URL-extension route would require a scene-message bridge and worker-compatible bundling; it is not validated here.

The [runtime](https://github.com/scratchfoundation/scratch-editor/blob/a71aeddc290c76a8e715ef74db1d81127afbc90d/packages/scratch-vm/src/engine/runtime.js) records event/hat metadata, namespaces opcodes by extension ID, and starts registered stacks through `startHats`. Explicit `isEdgeActivated: false` avoids per-tick predicate activation for the ITCH events. Our scene subscription invokes `itch_whenSceneChanges`; a changed `derived.currentWord` also invokes `itch_whenWordChanges`. The contract tests use callbacks, while a separate Node integration test executes actual Scratch threads.

The [VM](https://github.com/scratchfoundation/scratch-editor/blob/a71aeddc290c76a8e715ef74db1d81127afbc90d/packages/scratch-vm/src/virtual-machine.js) starts its runtime using `start`, uses `greenFlag` to launch project stacks, and provides asynchronous `loadProject` parsing/validation for Scratch project inputs. Target installation waits for project extension loading. A real player will need renderer/storage setup, actual extension-load readiness, project lifecycle and cleanup tests. `apps/player` currently contains none of that playback path.

The VM's [video IO abstraction](https://github.com/scratchfoundation/scratch-editor/blob/a71aeddc290c76a8e715ef74db1d81127afbc90d/packages/scratch-vm/src/io/video.js) accepts a provider exposing `enableVideo`, `disableVideo` and `getFrame` (dimensions, mirroring, format and cache options). The [GUI implementation](https://github.com/scratchfoundation/scratch-editor/blob/a71aeddc290c76a8e715ef74db1d81127afbc90d/packages/scratch-gui/src/lib/video/video-provider.js) owns the camera lifecycle and sampling workspace. ITCH's frame source remains independent; no Scratch video provider is installed in this baseline. Shared camera ownership and one-time mirror compensation require a later real-runtime test.

**T-P0-02 passes as a Node integration spike:** `packages/scratch/test/real-vm.test.ts` registers through the real extension manager, waits for asynchronous primitive installation, checks version/ready reporters, creates an assetless stage with real Scratch blocks, and manually steps the sequencer. A scene-change hat increments a Scratch variable; movement increments it again, repeated scene content does not, and disposal suppresses subsequent events.

The pinned package's default Node bundle failed while resolving `browser/default-stylesheet.css` in this environment, so the test resolves the package's shipped `src/index.js` instead. The extension manager, blocks and sequencer are real; no renderer or runtime timer is used. The VM is a test-only dependency. Browser integration, URL sandboxing/distribution, loaded-ID/project persistence, .sb3 playback and same-device mobile camera/playback remain open. See [ADR-001](../adr/001-scratch-integration.md).
